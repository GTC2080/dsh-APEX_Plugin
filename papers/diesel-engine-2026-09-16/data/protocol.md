建立日期：2026-09-16（Australia/Sydney）。状态：**案例已准备，尚未执行模型生成或成品评分**。

本案例沿用已有 Poolrooms benchmark 的资料结构，评价完整工程交付、机械运动、交互、视觉和性能。它包含固定题目与可执行的验收步骤，不包含自动运行 Harness 或自动判定视觉质量的程序。

- [`rubric.md`](./rubric.md)：100 分量表、证据要求和硬上限，仅供评测方使用。

向被测模型只发送 `prompt.md` 正文。不要追加隐藏量表、参考公式、实现模板或针对某个预设的补提示。原题不要求单 HTML，也不限定 Three.js；可直接运行的 Unity/Unreal 交付与 Web 交付均可参测，但不同运行平台的帧率不直接比较。

## 范围与解释

1. 未指定机型、缸数、缸径、行程、连杆长度、具体气门正时或真实 CAD。允许模型选择单缸或多缸、合理尺寸及配气方案；应明确选型和尺寸依据。参数自洽不等于复刻某台量产发动机。
2. 明确列出的部件均须检查；涡轮增压器因“若有”可不适用。中冷器没有这一限定，仍保留检查，缺失须记录，不能自动随涡轮一同豁免。自然吸气方案不能把未接入气路的装饰盒计作可工作的中冷器。
3. “可拆解级精度”检查部件可辨认、层级与装配关系；允许通过剖视、隐藏或分解观察内部。完整维修步骤、自动拆装教程、任意零件拖拽不是额外必选功能。
4. 允许教学运动学和示意流动；原题没有要求 CFD、有限元、实测燃烧压力或真实热力学求解。水温、油压须注明为模拟值，并与声明的工况模型一致。
5. 0.1 mm 按声明单位与几何基准检查，不能由小数位数、模型精细外观或高面数推出。没有原厂尺寸资料时，最多验证声明几何的一致性；制造公差与实机复刻准确度保持未验证。
6. 理想气门正时和声明了提前、迟闭、重叠的正时均可；评测不得把真实合理的重叠误判为错误。仅写“四冲程”“PBR”“60 fps”的文字没有对应功能分。

## 固定验收步骤

### T1：启动与环境记录

从冻结成品的真实入口启动，按其操作说明执行。Web 交付使用固定本地 HTTP 静态服务或交付中已有的项目命令；原生交付使用声明的可执行入口。记录浏览器/引擎版本、OS、CPU/GPU、图形 API、硬件加速、显示刷新率、窗口与画布实际像素、DPR、质量档位、资源请求及错误。Web 基准窗口 1440×900、DPR 1；原生使用同等渲染分辨率并记录差异。启动失败须区分成品错误、依赖服务失败和评测环境问题。

### T2：部件清单与真实拾取

按照量表 S1–S8 建立清单，记录每个部件的几何对象、装配位置、可见方式、材质、信息卡和证据位置。图例文字不代替几何；相同零件可以实例化，不要求每个螺栓成为单独源码文件。

运行抽查固定件、运动件、配气、燃油、润滑、冷却、进排气和细节件，每组至少一个已建模对象；另查活塞、连杆、曲轴、进气门、排气门、喷油器，总计至少 12 个不同对象。缺失对象保留为失败项，不能换成更容易通过的对象。鼠标必须移动到可见几何表面；验证旋转/缩放后仍可拾取、移开后信息卡更新或消失、剖视后能选到内部零件。结合全对象拾取映射检查覆盖范围，抽样通过不得写成所有零件均已实测通过。

### T3：四冲程与几何运动

本协议约定 `θ=0°` 为该缸进气开始的上止点，正向循环为 720°。允许成品采用其他零点或旋向，先按其定义变换后比较；多缸按各缸相位分别检查。

| 归一化曲轴角 | 活塞运动 | 理想正时的气门状态 | 阶段 |
| --- | --- | --- | --- |
| 0° ≤ θ < 180° | 上止点至下止点 | 进气开、排气关 | 吸气 |
| 180° ≤ θ < 360° | 下止点至上止点 | 两阀关闭 | 压缩 |
| 360° ≤ θ < 540° | 上止点至下止点 | 两阀关闭 | 做功 |
| 540° ≤ θ < 720° | 下止点至上止点 | 进气关、排气开 | 排气 |

该表给出冲程内部的理想状态，气门在切换点可处于零升程；真实提前/迟闭和重叠按成品声明的连续升程曲线核对。喷油与压燃应处于压缩末期附近，而非吸入预混燃油后由火花塞点火。柴油循环依据见 [DOE 的内燃机说明](https://www.energy.gov/cmei/vehicles/articles/internal-combustion-engine-basics) 和 [Cummins 的柴油机工作过程](https://www.cummins.com/en-na/news/how-do-diesel-engines-work)。

对中心对齐的曲柄连杆机构，以 `r` 为曲柄半径、`l>r` 为连杆两孔中心距、`s` 为活塞从上止点向下的位移，独立几何基准为：

```text
a = θ × π / 180
crankpin = (r sin(a), r cos(a))
pistonpin = (0, r cos(a) + sqrt(l² − r² sin²(a)))
s(θ) = r + l − pistonpin.y
stroke = 2r
|pistonpin − crankpin| = l
Vc = (π × bore² × stroke / 4) / (compressionRatio − 1)
```

曲柄连杆关系可对照 [Penn State 的几何解](https://www.me.psu.edu/sommer/me481/h03_solution.pdf)。偏置机构可以用其声明的轴线与孔中心直接核对长度约束，不能硬套中心对齐公式。计算出来的参考数字只是评测基准，必须与成品实际驱动的节点变换/几何对比；另写一份正确公式不证明成品正确。

依次检查 `0, 45, 90, 135, 180, 225, 270, 315, 360, 405, 450, 495, 540, 585, 630, 675, 720°`；另查 `179/181、359/361、539/541、719/721°` 的跨界连续性，以及第二个周期到 1440° 的重复性。记录角度、活塞位置、连杆两端、曲轴销、凸轮角、两阀升程、气门弹簧和当前标签。动画同一相位在不同播放速度下应给出相同构型。

凸轮轴一循环转一圈，曲轴转两圈；依据传动形式，旋向可同向或反向，按展开角检查 `Δcam = ±Δcrank / 2` 及固定相位偏置。仅 0°/720° 的两个取模角不足以证明转速比。该机械关系也见 [AIP 对四冲程实物机构的说明](https://students.aip.org/observer/the-applied-physics-of-gasoline-engines-part-1)，这里只引用其齿轮与凸轮机构，不采用汽油机点火方式。

原题未要求相位拖动/单步按钮；有则使用，没有则采用慢速录取或外部只读观察。需要仪器化时使用单独测量副本并记录改动，不能改写原始成品或用注入的正确动画替代交付。无法采集的数据标记未验证。

### T4：调速、流动与工况

记录速度控制的实际范围，在其范围的 25%、50%、75% 三档检查构型、相位和流动，并区分物理转速与用于观察的播放倍率。用真实时间差检查角度推进；相同转速/倍率下，30/60/120 Hz 的驱动采样不应改变单位时间运动量。此采样是运动逻辑检查，不是帧率测试。

保持相机固定，跟踪冷却液从泵经水套、节温器/散热或旁通再回泵的可达通路，跟踪润滑油从油底壳经泵、过滤与油道到润滑点并回流的通路。具体过滤器/冷却器顺序按声明布局，不能把互不相连的彩色线段视为回路。改变可用的转速与负荷，分别记录粒子通过截面的数量或流线速度，以及水温/油压变化；允许调压、温控、饱和和延迟，不强求线性增长。缺少可操作或可观察的负荷路径时明确标记，不能假定已经验证。

若交付提供暂停、停机或复位，检查其声明语义和恢复同步；原题没有强制这些按钮，缺失不单独扣分。模拟暂停与真实发动机停机要区分；后者允许模型中明确说明的惯性或延迟散热。

### T5：材质、剖视和视角

依次切换俯视、侧视、剖视、自由视角，执行旋转、缩放、平移。验证半透明/剖视一键切换前后确实暴露内部几何、油道和气道，不只是改变背景或显示文字。查看金属、粗糙表面、橡胶的材质响应；检查透明排序、遮挡、深度与可读性。比较正常装配和内部观察状态，不能通过移走运动零件掩盖装配干涉。保存全机、内部配气、曲轴连杆和至少一张实际悬浮卡截图。

### T6：0.1 mm 与间隙

记录场景单位到 mm 的换算和名义尺寸依据。至少检查缸径、行程、曲柄偏心距、连杆中心距、活塞销直径、最大气门升程，以及活塞/缸壁、轴颈/轴承、活塞/气门的间隙；压缩比与声明的排量、余隙容积保持一致。维度分别测量，不能用全机包围盒替代内孔和销孔尺寸。

在真实世界变换后比较几何与名义尺寸，记录各项绝对误差和最大误差。曲面还需检查离散网格对名义曲面的偏差，例如圆柱截面内接多边形的最大弦高；小于 0.1 mm 的位移增量或浮点精度不证明曲面达到 0.1 mm。声明几何一致性达到 0.1 mm 的判断要求受检误差均不超过该值，并注明覆盖范围；未采样部位保持未验证。

间隙必须有尺寸依据且与装配/运动一致，不能统一扩大为可见大缝。可通过放大或标注观察微小间隙；剖视或示意放大须说明。没有真实机型的参考图纸/CAD，实机尺寸准确度和制造公差不予认证。只按证据给予量表 D 项分数，不把这一限制改写为已经满足用户全部精度要求。

### T7：真实渲染与性能

在同一硬件、分辨率、质量、前台可见状态下，分别测试默认外观、剖视且两种流动开启、剖视且进行相机旋转的场景。选择 T4 的 75% 速度档；如可调负荷，使用 75% 负荷。每种状态预热 5 秒、采样 30 秒，只执行一遍固定序列，记录平均有效帧率、逐秒帧率、p95/p99 帧时、超过 33.33 ms 的帧数、错误和测量方法。

“有效帧”须有当前场景确实绘制并持续更新的证据。优先使用引擎或浏览器的帧呈现统计；只有 rAF 回调、函数调用计数、插桩 Canvas 统计或页面自报 FPS 时，将其单列为代理指标，不能证明实际 GPU 呈现吞吐量。未能获得可靠帧测量时标记未验证，不填 0。无头/软件渲染与前台硬件加速结果分开，不用无头结果认证实机 60 fps。

本案例的性能记分规则：三个状态平均有效帧率均至少 60 才满足 P1；逐秒下界和卡顿按 P2 另评。平均值通过不代表每帧都达标；若稳定卡在显示刷新率边界，保留原始值和“刷新率受限”说明，不能向上取整制造通过。最慢/最差场景决定该项结果，不挑选最好的一秒。测量所需的附加探针与原成品分开，记录开销；不得悄悄降低画质、分辨率、零件或流动数量。

### T8：冻结评分与报告

逐项填写分数、状态和证据，再按量表应用全部适用硬上限。分别报告成品质量、需求完成情况、自然完成/预算终止、时间、用量、工具错误、评测污染和人工介入。工具次数、截图张数、自写测试数量都不是质量分。

`cases` 只追加真实运行记录，不预填虚构样本。每个 case 至少保存匿名编号、实际配置与限制、成品摘要、运行状态、介入标记、逐项 `points/status/evidence`、原始分、适用硬上限及最终分，以及相位采样、部件清单、尺寸误差、性能原始摘要。评分上限是 `min(原始分, 所有适用上限)`。

状态分别使用 `passed`、`partial`、`failed`、`not-verified`、`not-applicable`；只有原文条件允许时才能不适用。未验证项目不授予无证据分，并单列待核对分值，报告“已验证得分”和不确定范围。环境故障不直接判作模型失败；若成品仍可独立评分，注明运行失败与成品评分是两个结论。基础设施错误导致无成品时总分为 `null`，不是 0。token 用量缺失也是 `null`，不能声称零成本。

`overallAcceptance` 只有所有必需行为获得证据、精度/性能条件满足时才能为 `passed`；存在确认缺项为 `failed`，只有未验证项时为 `not-assessed`。分数高不自动等于完整满足原题。单次样本不证明某预设稳定更强。
