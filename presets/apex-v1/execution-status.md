# APEX 执行状态反馈（可选研究功能）

目的：完整 APEX 使用 `bash` 或 `apex_run_script` 后，即使生成的 PTC 代码漏掉返回值，下一模型请求也能收到异常执行事实。这只改善信息传递，尚未证明模型决策或任务效率提升。

## 接入与回退

本模块随 APEX 源码分发，默认 bundle 不加载。已安装当前 APEX 的 Host 可显式追加官方配置层：

```sh
dsh web --patch /absolute/path/to/dsh-apex/presets/apex-v1/execution-status.patch.yml
```

源码启动使用 `pnpm dsh web --patch ...`，沿用现有 Home 和 profile。此命令是接入说明；开发验证不会自动启动或重启用户的 Host。先确认旧进程已退出，避免两个 Host 同时操作同一 Home。

配置层通过现有包导出加载模块，只对实际挂载 `apex-v1` 的会话生效，不修改官方预设或复制 APEX 配置。Host 启用后，已存在和新建 APEX 会话的后续调用均受影响；Standard、Minimal、PTC 不增加此反馈。

回退时移除该 `--patch` 并在会话空闲后重启。已写入的历史观察仍保留；回退只停止新增观察。组件内卸载配置行也会撤销监听。

## 行为与边界

- 嵌套调用转入后台时保留作业编号和前台等待上限；这是返回时状态，当前状态仍需查询原生作业工具。
- 非正常前台结果分别保留退出码、信号、超时、取消和等待上限，不由退出码零推断完整成功。
- 正常成功、主动后台启动、直接工具调用、权限拒绝、取消中的调用及其他预设不增加观察。其他后置策略替换结果值时不根据旧值补发。
- 使用原生 `additionalContexts` 与会话日志；不复制命令、脚本、标准输出、错误文本或工作目录。原始结果、工具声明、权限、初始系统提示保持原样。
- 不执行重试、作业查询、进程清理或任务完成判定；既有浏览器引导继续由原模块负责。
- 每次符合条件的调用一条观察，可能与程序已经输出的状态重复。不同调用即使退出码相同也保留独立编号，不按错误码去重或静默截断。
- 上下文随异常次数线性增长，复用原生压缩；压缩摘要是否保留关键事实依赖摘要模型，本模块不承诺压缩后永久保全。没有额外缓存、队列或状态数据库。
- 其他外层后置策略仍可改写结果或移除上下文。该功能不恢复解释器内部已吞掉的失败，不覆盖 PowerShell，也不承诺任意第三方策略组合。

## 验收与验证

验收基线为完整 APEX V1.0。启用前后保持工具与 persona 相同，只改变状态反馈。验收包括：无输出的失败可见、原结果不变、两种执行工具覆盖、官方模式隔离、策略兼容、会话恢复、卸载与重复挂载、异常批次的消息数量和字节开销。

```sh
node --test test/apex-v1-execution-status.test.mjs
```

测试使用项目现有原生服务夹具和脚本模型，不请求真实模型 API。macOS 当前 official Harness 构建是开发验证环境；Linux、Windows 和真实模型效果需另行验证。付费对照的采用指标应是错误判断、重复操作、完整交付及总耗时；工程检查通过本身不构成模型收益。
