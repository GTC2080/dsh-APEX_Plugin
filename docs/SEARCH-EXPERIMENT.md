# APEX 搜索算法实验接入

状态：已实现实验接入并完成定向检查；本文件不代表算法收益已被证明。

## 最小实现

- 目标：让插件实际决定下一次修复哪个候选，并留下可核对的执行记录。
- 适用任务：工作区中的纯 ESM `solver.mjs` 导出同步 `solve(input)`；用户提供固定的 `public-cases.json`（`input` / `expected`）。本版本不处理网页、跨文件项目和无可执行判据的问题。
- `apex_search` 读取并执行真实源码，不接受模型自报通过率。相同源码按摘要识别；按所有公共点的规范化结果分组，不删除行为相同而源码不同的成员。
- 配置 `mode` 为 `off`、`program` 或 `behavior`；默认 `off`。后两者共享工具、提示、反馈、失败计数、候选数上限、重新生成入口和终止规则，只改变抽样单位。
- 初始候选与后续修复都由模型真实生成。公共全过立即停止，避免为触发机制而强行生成更多候选；未触发也是结果。达到局部搜索上限后，只按公开成绩及固定平局规则返回候选，不接触私有判分。
- 插件保存每份候选摘要、公开结果、失败次数、抽样分数及实际选中的父程序。选中的源码写回工作文件，下一次提交必须匹配待处理票据。正式最终验收独立进行。
- 单会话状态有界。进程重启或写入／执行状态不明时拒绝继续该次搜索，不声称支持透明恢复。保留候选原件与日志供复核。

## 复用与边界

复用现有工具注册、原生文件系统原子写入、进程沙箱和托管子进程取消、会话日志和后台任务。新增一个选择器与一个工具模块，不引入第三方依赖、模型路由服务、数据库或新 Harness Home。基于内容与 live APEX 一致的干净发布分支开发，避开原工作区的未提交修改。

共享候选执行器将输入作为 JSON 文本解析，保留顶层、嵌套对象与数组中的 `__proto__` 等自有成员及字符串转义。候选搜索、证据流程和原生反馈共用此入口。旧执行记录若受此前对象字面量丢键影响，应保留原记录并重新测量；检查点重放与冻结观察不一致时会拒绝继续。

### 配置

在预设的 `apex-search` 条目配置 `mode: program` 或 `mode: behavior` 启用；`off` 为默认。当前执行路径仅支持 macOS / Node 24。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| initialCandidates | 3 | 初始候选上限，1–3 |
| maxCandidates | 6 | 正式候选机会的计数上限，最多 6；不是模型请求数或 token 硬上限 |
| evaluationTimeoutMs | 10000 | 单批公共输入执行时限，100–20000 ms |
| seed | 随机生成并记录 | 固定实验抽样随机源；不控制模型采样 |
| useSeedPool | false | 从固定 `search-seeds.json` 导入共享初始化；每份源码重执行核对 |

共享池包含 `suiteHash` 和按启动顺序排列的 `sources`：各项为 `source`、`sha256`、`outcomes`。必须由先前真实公共执行产生；不接受部分初始化或伪造分数。该功能不恢复旧会话、未决票据或模型历史。默认首次调用 `apex_search({action:"start"})`，之后提交 `{action:"submit",ticket:"返回的票据"}`；`status` 读取同一决策而不重新抽样。

实验审查配置为 `apex-review.config.backgroundOnly: true`，强制通过原生后台 Job 执行，并用独立的 `job_output` 调用收集。默认 false 保留旧调用方式；后台完成仍须收集结果，不能用“已启动”代替“已审查”。

公共候选执行与最终判分均有独立限制；限制只约束程序执行，不强行终止模型的整个任务。生成阶段读取隔离不足时如实报告。原生后台子任务用于解决长审查被 PTC 上限截断的问题；用量无法补齐时仍记未知。

模型仍可在正式提交前进行多次内部编程、自测和工具调用，甚至不采用搜索入口；这些成本均须计入。源码恢复、票据和最终摘要核验提供可审计约束，不是对工作文件的永久写保护。不能将一次正式提交描述为一次未经修改的模型生成。

## 验收与回滚

1. 关闭模式不注册新工具或注入搜索提示。
2. 两种模式在全单成员情况下退化为相同选择；分组与失败计数、重新生成入口、重复源码和预算消耗经过检查。
3. 使用真实 Harness 工具和模型循环的无付费检查，确认候选执行、父程序切换、最终文件、异常／取消及会话隔离；不能只测试纯函数。
4. 通过包内容、语法和针对性回归检查后，冻结新实验并运行付费测试。至少分别报告机制是否发生、最终独立质量、全部可得用量与缺失。
5. 回滚为 `mode: off` 或选回 `apex-v1`。实验使用独立命名预设；没有覆盖已安装正式预设、修改已有实验原件或发布 GitHub。

## 首批付费观察（2026-09-17）

在官方 Harness 和 `deepseek-official / deepseek-flash / max` 上，对一般图最大权匹配和有向图最小树形图进行冻结预实验。共运行 6 个付费根会话、10 个父子会话，对应官方原生、APEX 关闭搜索、逐程序搜索、逐行为组搜索四条条件路径。

所有交付均通过对应的 79 项或 103 项独立检查。两个共享初始化都在首次正式提交公共全过，逐程序和逐行为组路径因此复用同一原件；实际父候选抽样为 0 次，不能认定选择策略有效或无效，也不能把两条派生路径算作两个独立成功样本。

关闭搜索的实验 APEX 对照在两题上记录的输出 token 分别约为原生的 5.98 倍和 5.66 倍，最终检查成绩相同。其中一个子任务还有传输失败后自动重试的用量缺口，因此记录值不是完整账单。这是两道手工任务、每条件一次的观察，不能推断普遍效率。

本次支持保留默认关闭的实验功能，并进一步研究由宿主直接串联生成、执行、选择与修复的局部控制器，以及验证工作的预算分配。尚不支持正式默认启用或能力提升宣传。完整冻结协议、运行记录、独立判分及审计保存在本地研究批次；没有发布新的正式版本。
