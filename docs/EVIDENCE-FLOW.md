# 宿主驱动的证据反馈实验

状态：已实现从头生成与同检查点配对入口，默认关闭。宽预算采集发现模型读取了评测参考实现及私有用例生成代码，该批次已停止且受污染结果不作为能力证据。本修订移除实验子会话的文件与搜索工具；尚无有效配对效果结论，没有替换正式安装。

## Feature Plan

- 用户目标：确保反馈选择实际进入下一次模型请求，减少对模型主动采用可选工具的依赖。
- 最小行为：`/apex_flow <原始任务>` 启动原生后台 Job，生成单文件 ESM、冻结源码、执行公共检查、选择反馈、修复、完整复测并交付冻结源码。
- 范围：macOS / Node 24，同步、有限 JSON 输入输出的 `solve(input)`；公共检查须给出期望来源。最多三次初始化、两次修复，每个子会话有时间上限。
- 非目标：KV Cache、模型训练、浏览器或多文件工程、额外摘要模型、父候选采样优化、通用代理框架、正式版本默认启用。
- 复用：现有候选执行器、源码摘要、规范化、受策略约束的文件接口、原生 `subagents` / `jobs` / `commands`。
- 文件：`evidence-flow.mjs`、`feedback.mjs`、`search.mjs` 的文件辅助函数、预设与针对性测试。
- 状态：读取并绑定公共检查 → 独立生成 → 冻结和执行 → 固定规则选父 → 反馈 → 独立修复 → 全集重放 → 冻结交付。异常或取消终止流程，不自动重试。
- 接口：增加默认关闭的实验模块及 `/apex_flow` 命令；原有搜索工具、正式包版本不变。
- 权限：实验子会话仅保留结构化交付工具；两策略权限相同。任务、父源码与选中反馈由宿主传入，完整公共套件、检查点、其他候选及参考实现不通过文件工具开放。源码由宿主写入并在既有沙箱中执行。该条件不同于完整工具权限的 APEX 工作流。
- 资源：有界候选数、证据条数与 UTF-8 字节、子会话截止时间、执行超时、源码与公共检查大小。原生会话日志保留实际请求和用量；缺失用量不计为零。
- 验证：纯函数边界、真实原生组件挂载与下一请求、后台生命周期、取消、输入/工件篡改、完整复测、关闭兼容、包内容检查。使用脚本化模型，无付费调用。
- 回滚：保持 `mode: off` 或移除实验模块配置；不迁移数据、不替换正式安装。

## 验收标准

- 命令直接启动宿主流程，父模型不先自行解题。
- 下一次原生请求准确包含原任务、父源码及本策略选中的完整证据；源码和检查摘要可追溯。
- 初始化公共全过立即结束；失败触发修复；单候选或签名退化仍可使用普通反馈，但记录选择研究未触发。
- 修复后完整检查，记录正确变错误的用例；按最高公共通过数、最早出现的并列规则交付。
- 完成前重新验证冻结输入和候选快照，重放交付源码并核对实际输出；不覆盖已有 `solver.mjs`。
- 取消、异常停止新模型调用，原生子会话及候选进程完成清理后 Job 才结束。
- 完成通知不会自动追加父模型调用；用户随后主动发消息可继续普通对话。活动流程不自动恢复，保留原始记录后另行处理。

## 实验用法

在隔离的研究预设副本中，将 `apex-evidence-flow` 行配置为下例。正式预设中的默认值为 `mode: off`；原 `apex-search` 保持关闭，避免同时改变父候选抽样。

```yaml
- id: apex-evidence-flow
  name: dsh-apex/apex-v1/evidence-flow
  config:
    mode: signature
    initialCandidates: 2
    maxRepairs: 1
    feedbackBytes: 4096
    feedbackItems: 4
    childTimeoutMs: 180000
    evaluationTimeoutMs: 10000
    maxTokens: 16384
    seed: 74193
```

比较反馈策略时仅将 `mode` 改为 `random`，其他条件固定。从头独立启动两组不能保证相同失败检查点；条件修复使用下文的配对入口，仍需先冻结实验协议。

### 同检查点配对修复

`/apex_repair checkpoint.json` 使用同一公共套件和冻结检查点，跳过初始化，仅启动一次修复。要求 `maxRepairs: 1`。两臂工作区各放入完全相同的检查点与 `public-cases.json`；只改变 `mode`，种子、资源限制和工具权限保持一致。

检查点 JSON 字段为 `task`、`taskHash`、`suiteHash`、`parentId`、`candidates`。每份候选含 `id`（源码 SHA-256）、`source`、`outcomes`（当时完整公共执行结果）。需要 2–3 份不同源码；固定父程序为公共通过数最多、并列时最早出现且尚未全过的候选。任务和套件摘要必须一致。

宿主导入后重新执行全部候选，对照冻结观察，再检查存在不同失败签名及不同可行反馈包。任何不一致、退化或配置错误均在模型调用前拒绝；随机恰好选中同包则保留。来源记录由实验采集与审计保证，插件不会自动证明候选是自然生成或参考答案正确。

检查点文件上限 1 MiB，沿用普通文件、路径、符号链接及摘要保护。报告记录检查点摘要和重放结果。子会话没有文件或搜索工具，不能通过这些工具取得检查点或完整公共材料。该变更改变了此前允许读取文件的实验条件，新批次需要重新冻结。原有 `/apex_flow` 流程及默认关闭状态保持不变。

准备没有 `solver.mjs` 和 `.apex-flow.json` 的工作区及 `public-cases.json`：

```json
[
  {"input": 3, "expected": 6, "expectedSource": "题面明确规定返回输入的两倍"}
]
```

公共检查为 1–256 条，总文件不超过 1 MiB。每条含有限 JSON 的 `input`、`expected`，以及 1–4096 UTF-8 字节的 `expectedSource`。插件检查来源字段存在并保留它，**不自动认证参考答案正确**；可信依据仍须研究者审查。

从空闲的父会话运行：

```text
/apex_flow 编写同步 ESM solve(input)，返回输入数值的两倍。
```

命令返回原生 `jobId`、`runId` 与报告文件名。通过原生任务列表和 `job_output` 读取，通过 `job_kill` 取消；会话销毁也会取消并等待子任务清理。命令已返回后，启动请求本身被取消不会误杀已发布 Job。

| 配置 | 默认值 | 上限及含义 |
| --- | ---: | --- |
| `mode` | `off` | `off` / `signature` / `random` |
| `initialCandidates` | 2 | 1–3；任一初始化公共全过即停止 |
| `maxRepairs` | 1 | 0–2；与初始化分开计数 |
| `feedbackBytes` | 4096 | 512–16384；完整反馈 JSON 数组的 UTF-8 字节 |
| `feedbackItems` | 4 | 1–8；长条目整体跳过，不截断成残缺事实 |
| `childTimeoutMs` | 180000 | 100–3600000；每个子会话的启动与模型阶段 |
| `evaluationTimeoutMs` | 10000 | 100–20000；每批完整公共执行 |
| `maxTokens` | 16384 | 256–393216；每次模型请求的输出上限，**不是全任务 token 预算** |
| `seed` | 运行时生成 | 可固定为 0–4294967295；实际值写入报告 |

源码最多 128 KiB，原始任务最多 32 KiB。命令启动时先读取父会话的待生效模型选择，再回退到实际请求记录、界面默认或创建配置；通过原生 LLM 配置解析后一次性固定所有子会话的路由与推理强度。不会为获取配置额外调用父模型。子会话仅开放原生 `structured_output`；继承工具的允许列表为空，执行守卫还会拒绝其他工具调用，包括文件读写、目录/内容搜索、Shell、PTC 执行和进一步委派。候选源码执行仍使用原有的权限受限 Node / Seatbelt 路径。

### 交付和审计

已核对的 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 将单请求上限列为 393216。宽预算研究可显式设置 `maxTokens: 393216`、`childTimeoutMs: 3600000`；默认值和默认关闭状态不变。上限是允许生成的空间，实际用量以日志为准；扩大上限后必须为新批次重新冻结两组条件，不能覆盖旧结果。

- `.apex-flow.json`：一次性工作区占用标记，已有文件则拒绝重新启动。
- `.apex-flow-<runId>-request-*.json`：送入子会话的原任务、源代码与反馈原文；实际模型请求仍以原生会话日志为准。
- 对应 `source-*.mjs`、`execution-*.json`、`feedback-*.json`：原件、公共执行事实、策略选择及匹配诊断。
- 对应 `report.json`：候选结果、子会话 ID、反馈条目编号、退化原因、回归用例、完整重放和最终摘要。
- `solver.mjs`：最高公共通过数的候选；并列取最早出现者。没有全部通过时仍可正常完成有界流程，但报告保留失败数，不能称任务完全成功。

报告中的 `usage` 是原生会话投影记录量。`settledWithoutUsage` 非零或 `usage: null` 表示存在未知消耗；不能当作零成本或完整账单。失败尝试与读取事件保留会话索引。研究分析必须进一步核对所有会话原始结算、重试、实际输入和缓存分类。

子会话没有自动继承父聊天；模型可获取的任务与反馈由宿主构造。实验审计仍须检查实际请求上下文及工具结果，不能仅凭配置宣称所有信息来源均已隔离。报告的 `reads` 字段记录读取类调用尝试，是否真正读取成功须结合原生工具结果判断。受污染历史样本继续保留并单独标识。若用户中途发消息继续父会话，该行为属于受控实验之外的干预。

源码和证据在运行及交付时有摘要复核；不是操作系统不可变文件。交付后外部修改必须按摘要识别，不能继续沿用旧判分。进程/网络隔离仍沿用现有执行器，本轮没有扩展成任意恶意程序的安全证明。

## 研究边界

从 C2C 借鉴“依据接收状态选择信息并检查负面迁移”的研究思路。这里传递可验证的文本执行事实，不是 C2C 的实现。

失败用例按各不同源码候选的通过/失败向量分组。分组不等于错误根因分类。每组按完整序列化条目的长度、用例原顺序排序，再按签名字典序轮流取条目。随机对照匹配条数及每条 256 字节长度分箱，受同一总字节上限约束；不是严格 token 匹配。偶然相同的随机包保留，不重抽。

当前只完成工程机制后才检查自然数据资格。合成夹具不进入能力效果结果。正式配对实验必须复用同一个失败检查点及候选池，预先冻结预算和种子；各自从头生成的两次运行不能用于归因反馈选择。

配对入口已完成。效果研究需先冻结自然失败采集任务与资源上限，按顺序选择合格检查点，再进行两臂付费修复。此前搜索初始化两题分别公共 22/22 和 24/24，各只有一份候选，不能用于这项条件修复实验。配置异常批次及其消耗须单独保留，不能静默重投或合并成有效配对。
